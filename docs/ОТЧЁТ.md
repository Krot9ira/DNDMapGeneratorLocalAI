## Вы были правы насчёт Ideogram, я ошибался

Я сначала сказал, что Ideogram — облачный API и что координаты в JSON это «просто
токены». **Обе оценки были неверны**, и я сделал их не проверив:

- Ideogram 4 — **открытая модель 9.3B**, работает локально. Я судил по категории ноды
  `partner/image` и не открыл ваш воркфлоу.
- Модель обучена **исключительно на структурированных JSON-капшенах**, и bounding box
  для неё — обученный интерфейс управления, а не текст.

Проверка вашего файла `image_ideogram4_t2i (3).json` показала настоящий локальный граф:
`UNETLoader` × 2, `CLIPLoader`, `VAELoader`, `DualModelGuider`, `Ideogram4Scheduler`.

**Почему это оказалось идеальным решением.** Архитектор уже знал точный прямоугольник
каждой комнаты, воды, корабля и предмета. Теперь планировка уходит в модель числами
(`[y1,x1,y2,x2]`, 0–1000), а не через ControlNet. Это убрало сразу оба ваших замечания:
следование схеме стало точным, а картинка перестала быть «раскрашенной картой высот»,
потому что ControlNet больше не давит на светимость.

## Что было исправлено по ходу

| Проблема | Причина | Решение |
|---|---|---|
| Текст в финальных картинках | подписи областей запекались в контрольное изображение | подписи живут только в `map.json` и превью; в картинку не попадают никогда |
| План генерился плохо | у LLM просили координаты сетки | LLM описывает сцену словами, геометрию считает `architect.py` |
| Интерфейс приложения сломан | `ImGui::Begin` внутри вкладок | вкладки на дочерних регионах; шрифт с кириллицей вместо эмодзи-квадратов |
| Редактор не работал | был только пан, без рисования | кисть, прямоугольник, пропсы, зум, undo/redo (60 шагов), «Rebuild walls» |
| Корабль не похож на корабль | 6 клеток высоты — негде разместить нос | корабль стал векторным объектом: нос, фальшборт, доски палубы, люк, мачта, ют |
| Пропсы как «кучки» | плоские блины в depth-карте | мелкий декор больше не прибивается к клетке — он только описывается, модель рисует сама |
| Здания внутри зданий | стиль просил черепичные крыши | «крыша снята, интерьер виден»; крыши в чёрном списке |
| Мультяшный стиль | я слишком ужал ваш референс | стиль возвращён к `Dnd drawnlike` (без абзаца про сетку) |
| Плоская «раскрашенная карта высот» | ControlNet strength 0.70 на всю длину | переход на Ideogram; ControlNet остался запасным путём |

Честно, чтобы вы не наткнулись неожиданно:

1. **Приложение один раз закрылось само** после успешного рендера (файл сохранился,

   Воспроизвести повторно не удалось. Стоит последить.
2. **C++-приложение не тестировалось с Ideogram** end-to-end. Код пути написан и
   собирается, но живого прогона из окна приложения не было — на это не хватило времени
   до вашего ухода. Python-путь проверен полностью.
3. **Второй проход (Flux 2 Dev, детализация)** реализован и работает, но выключен:
   `config.json` → `comfy.refine.enabled = false`. Ideogram и так рисует сразу в нужном
   разрешении. Включите, если захотите поэкспериментировать.

## Как пользоваться

**Приложение:** `bin\Release\DndBattlemapGenerator.exe`
Вкладка Create → опишите сцену → выберите стиль и размер → **MAKE MY BATTLE MAP**.

**Командная строка:**
```
python pipeline.py auto "порт с большим кораблём" --style city_harbour --size large
```

**Перед запуском** должны работать ComfyUI (порт 8188) и Ollama (порт 11434).
Проверка одной кнопкой: вкладка Settings → *Test both connections*.
